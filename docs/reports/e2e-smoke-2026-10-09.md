## Failures

### 1. Price lists on a phone: a link inside a link (bug) — FIXED

| | |
|---|---|
| Where | `/master/price-lists`, phone (below 768 px) |
| What the browser says | React: `<a> cannot be a descendant of <a>` (invalid HTML) |
| Cause | On a phone every table row becomes a card that is itself a link (`components/common/CardList.jsx`). The first column of the price lists renders its own `<Link>` (`pages/master/price-lists/PriceListsPage.jsx:29`), so the card is a link that holds another link to the same page. |
| What the user sees | The card works, but a screen reader announces two links, and some browsers move the inner link out of the card (broken layout). |
| Fix done | `CardList` no longer wraps the card in a link: a link is laid **over** the card (`absolute inset-0`, named by the title), and the links and buttons inside the cells stay clickable on top of it. This fixes every list on a phone, not only the price lists (quotations, sale orders, the journal and the stock movements also hold links in their cells and would have shown the same error with data). New tests: a unit test of `CardList` (no `a a`) and the e2e case *a card of the price lists opens its sheet, and no link holds another link*. After the fix the whole smoke test passes (13 + 1). |
| Evidence | `frontend/e2e-results/…-phone/video.webm`, `trace.zip`, `test-failed-1.png` (not committed; made again by running the test) |

No other page failed at any size.
